1. Présentation

Mini-CMS est une application web de gestion d'articles (posts) avec catégories, tags, authentification utilisateur et une API REST. Elle est le projet fil rouge de l'Atelier Framework Côté Serveur (ISET Sidi Bouzid, 3e année MDW, groupe MDW33) et couvre le cycle complet d'une application Laravel : MVC, base de données, relations Eloquent, validation, autorisations, API et tests automatisés.

Le projet a été construit au fil de 15 sessions de cours, chaque session donnant lieu à un commit dédié sur la branche mini-cms.

2. Fonctionnalités

Articles (Posts)

  • CRUD complet (création, lecture, modification, suppression)
  • Publication / dépublication (toggle)
  • Archives par année
  • Filtrage par catégorie et par tag
  • Liste "mes articles" (auteur connecté)
  • Pagination

Taxonomie

  • Catégories (admin CRUD)
  • Tags (admin CRUD)
  • Relation N:N posts ↔ tags
  • Chargement anticipé (eager loading)
  • Compteur d'articles par catégorie

Authentification

  • Inscription / connexion manuelles
  • Rôles : author, admin
  • Gates & Policies (PostPolicy)
  • Middleware admin, writable, auth, guest
  • Jetons Sanctum pour l'API

API REST

  • Lecture publique (index, show)
  • CRUD protégé par Sanctum
  • API Resources (PostResource, CategoryResource)
  • Validation (Form Requests) + pagination
  • Codes HTTP : 200, 201, 204, 403, 404, 422

7. Authentification & autorisations

7.1 Authentification manuelle

  • RegisterController : création de compte (rôle author par défaut), connexion automatique.
  • LoginController : connexion par email/mot de passe, déconnexion.
  • LoginRequest, RegisterRequest : validation.
  • Vues : auth/login.blade.php, auth/register.blade.php.
  • Routes groupées : guest (inscription/connexion), auth (déconnexion).

7.2 Rôles & Gates

  • Colonne role sur users (author par défaut, admin).
  • Gate manage-categories : réservé aux admins.
  • Gate manage-tags : réservé aux admins.

7.3 Policy (PostPolicy)

  • view : article publié OU auteur/admin.
  • create : utilisateur connecté.
  • update / delete : auteur de l'article OU admin.

7.4 Middleware

  • auth : utilisateur connecté.
  • guest : visiteur non connecté.
  • writable (EnsureSiteIsWritable) : bloque les écritures si SITE_READ_ONLY=true → 503.
  • admin (EnsureUserIsAdmin) : réserve /admin aux admins.

Préfixe /api. Lecture publique, écriture protégée par Sanctum (jetons).

PUT/PATCH/api/posts/{post}ModifierSanctum + auteur/admin
DELETE/api/posts/{post}SupprimerSanctum + auteur/admin
POST/api/registerInscription → jetonNon

POST/api/logoutRévocation du jetonSanctum
GET/api/userUtilisateur connectéSanctum

8.2 Resources

  • PostResource : id, title, slug, excerpt, body, published_at, author, category, tags.
  • CategoryResource : id, name, slug.

8.3 Codes HTTP

200 (OK), 201 (Created), 204 (No Content), 403 (Forbidden), 404 (Not Found), 422 (Validation), 401 (Unauthenticated).

9. Validation & Form Requests

  • StorePostRequest / UpdatePostRequest : title, slug unique, excerpt, body, published_at, category_id, tags.
  • StoreCategoryRequest / UpdateCategoryRequest : name, slug.
  • StoreTagRequest / UpdateTagRequest : name, slug.
  • LoginRequest / RegisterRequest : email, password.
  • Api/IndexPostRequest : per_page (1–50).

Messages de validation en français (lang/fr/validation.php, APP_LOCALE=fr).

11. Pages d'erreur

  • errors/404.blade.php — ressource introuvable.
  • errors/503.blade.php — site en lecture seule.
  • errors/article-introuvable.blade.php — article non trouvé.
  • errors/layout.blade.php, errors/minimal.blade.php — layouts d'erreur.
  • Réponses JSON pour les routes /api/* (via shouldRenderJsonWhen).
